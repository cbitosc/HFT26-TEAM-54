# P2 explained: ZK + attestation (plain English)

Status: toy circuit done and pushed. Real circuit, prove.js, cheat_demo.js and attest/sign.py are NOT written yet.

## What each file does

### zk/toy/ (a tiny practice circuit)
| File | What it does |
|---|---|
| `toy/toy.circom` | The practice circuit. It says: "I know two numbers a and b (0-255) where a < b." `a` and `b` are public. If the claim is false, no proof can be made. |
| `toy/input.json` | The sample numbers we prove with: a = 3, b = 10. |
| `toy/out/verification_key.json` | The public "checking key" for this circuit. Anyone can use it to check a proof. It cannot be used to make proofs. |
| `toy/out/Verifier.sol` | A smart contract (named `Groth16Verifier`) with the checking key built in. Its `verifyProof` function answers true or false. |
| `toy/out/proof.json` | A sample proof for a = 3, b = 10. |
| `toy/out/public.json` | The public values for that proof: `["3", "10"]`. |
| `toy/out/calldata.txt` | The proof and public values formatted so they can be pasted straight into `verifyProof`. |

### zk/ (setup, not committed)
| Item | What it does |
|---|---|
| `package.json`, `package-lock.json` | The list of JavaScript libraries (snarkjs, circomlib, circomlibjs, ethers, dotenv) and their exact versions. |
| `ptau/pot12_local_final.ptau` | The "Powers of Tau" starter file for the trusted setup. Git ignores it (it is a big binary). |
| `toy/build/` | Compiler output (constraints, witness program, proving key). It can be regenerated, so it is not committed. |

### attest/
Empty so far. It will hold `sign.py`, where the evaluator signs the metrics (PLAN.md section 3.6).

## How the toy was made (the pipeline in 6 steps)
1. Write the rule in circom (`toy.circom`).
2. Compile it to constraints and a witness program (`circom`).
3. Setup: combine the circuit with the ptau file to make a proving key and a checking key (`snarkjs groth16 setup`, then one `zkey contribute`).
4. Prove: give private/public inputs, get a small proof (`snarkjs groth16 fullprove`).
5. Verify: check the proof with only the checking key (`snarkjs groth16 verify` printed `OK!`).
6. Export the checking key as a Solidity contract so a blockchain can do step 5.

Negative test: with a = 10, b = 3 the witness generator stops with `Assert Failed` at the line `lt.out === 1`. No witness means no proof, so a false claim cannot be proven.

## Honest notes (say these if asked)
- **The ptau file is local, not the official ceremony.** The official `powersOfTau28_hez_final_12.ptau` URLs (Google and Hermez) returned HTTP 403 on 2026-10-30, so we generated our own with snarkjs and one contribution (me, using random bytes from this laptop). The maths and file format are the same, but the trust is weaker: whoever ran it could in theory forge proofs. Fine for a toy; replace it with the official file (checksum published in the snarkjs README) before the real circuit if we can get it.
- The toy verifier checks 2 public signals. The real one will check 16 (PLAN.md section 3.5), so its Solidity function signature will be different.
- `docs/roles/P2.md` is still a placeholder from P3, so steps were taken from the task message and PLAN.md.

## How to explain this to judges (3 sentences)
A zero-knowledge proof lets our agent show that its scores really improved from version 1 to 2 to 3, using our fixed scoring formula, without revealing its secret system prompt. The proof is tiny, and a smart contract can check it in one call, so nobody has to trust the agent's word. We tested the idea first on a toy circuit ("a is less than b"): a true claim verifies, and a false claim cannot even produce a proof.
